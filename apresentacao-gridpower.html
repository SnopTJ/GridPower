Modelagem Matemática

Grafo não direcionado ponderado + Árvore Geradora Mínima

A rede urbana é modelada como um grafo G = (V, E) onde:

Vértices V

  • |V| = 12 pontos de infraestrutura
  • Tipos: Subestações, Quadros, Estações, Reservatórios, Consumos
  • Cada vértice tem identificador único e coordenadas (para visualização)

Arestas E

  • |E| = 17 conexões candidatas
  • Peso = custo de implantação (R$)
  • Grafo conexo: existe caminho entre quaisquer dois vértices
Objetivo: Encontrar subconjunto T ⊆ E tal que:
(V, T) é uma árvore  ∧  Σe∈T custo(e) é mínimo
AGM existe e é única (custos distintos)

Algoritmos Implementados

Duas abordagens clássicas para AGM

🔷 Prim (Heap Mínimo)

  • Inicia em vértice arbitrário
  • Mantém fronteira no heap de prioridade
  • Sempre expande com aresta de menor custo
  • Complexidade: O(|E| log |V|)
  • Ideal para grafos densos
  • Estruturas: Adjacência + Heap binário

🟠 Kruskal (Union-Find)

  • Ordena todas as arestas por custo
  • Processa em ordem crescente
  • Adiciona se não forma ciclo (Union-Find)
  • Complexidade: O(|E| log |E|)
  • Ideal para grafos esparsos
  • Estruturas: Lista de arestas + Union-Find com path compression
Prim: cresce uma única componente
Kruskal: mescla componentes floresta

Ambos garantem AGM ótima. A implementação compara resultados para validar correção.

⏱ Tempo de Execução

  • Kruskal ~15-20% mais rápido
  • Ambos sub-lineares na prática
  • Ordenação (Kruskal) vs Heap (Prim)

💾 Pico de Memória

  • Kruskal usa ~55% menos memória
  • Prim: adjacência (2|E|) + heap
  • Kruskal: arestas ordenadas + Union-Find (|V|)

Conclusão: Em redes esparsas (|E| = 5|V|), Kruskal supera Prim em tempo e memória. Para redes densas, Prim com heap de Fibonacci seria preferível.

Arquitetura do GridPower

Código limpo, testável e extensível

📦 src/modelos/

  • Vertice — id, nome, tipo, coordenadas
  • Aresta — origem, destino, custo, chave única
  • Grafo — adjacência, validações, conectividade
  • UnionFind — path compression + union by rank
  • MST — árvore resultante (arestas, custo, algoritmo)

⚙️ src/algoritmos/

  • prim.py — heapq, O(|E| log |V|)
  • kruskal.py — UnionFind, O(|E| log |E|)
  • Núcleo matemático puro, sem I/O

🔧 src/servicos/

  • servico_rede.py — orquestra Prim/Kruskal, compara
  • relatorio.py — gera Markdown técnico
  • experimento.py — benchmark automatizado

📊 src/dados/ & utilitarios/

  • exemplos.py — rede do artigo (12 pontos)
  • gerador.py — redes sintéticas conexas
  • visualizacao.py — matplotlib (layout circular)
